## Byte-only checker contract

`assessS34B23DisposableMigration` only accepts:
- exact `scope=G7-S3-4B2-3-DISPOSABLE-ONLY` and schema ID
  `202610260002_g7_operational_auth`;
- an opaque `SNAP-*` label, supplied before/after *in-memory SQLite Buffers*;
- synthetic Local/S3 export Buffers with an exact DB Version ID, storage
  locator, and storage kind; bounds reject large/extra malformed payloads.

It opens both provided SQLite Buffers as new memory clones. It does **not**
open a filesystem path, run a migration command, contact OCI/DB/S3, stop
writers, or mutate an operating database. For each clone it runs SQLite
`quick_check` and `foreign_key_check`, verifies the exact seven CAD table
inventories, and requires their **complete row-for-row equality** across
the seventh SQL including hierarchical ownership, Current, Version,
nextVersion, file_size, SHA-256 and storage_path. Every synthetic Local
file and S3-export buffer is hashed independently and checked against the
CAD Version row (including distinct object/DB UUID semantics); require both
storage kinds and one-to-one coverage.

The baseline must have no Auth tables; the candidate must have all **eight**:
`User`, `UserRoleGrant`, `UserSiteGrant`, `SpecialGrant`, `AuthSession`,
`AuditEvent`, `AdminRecoveryNonce`, `G3LoginAttempt`. Verify the
`g1_audit_no_update`/`g1_audit_no_delete` triggers and actively attempt
UPDATE and DELETE of a synthetic AuditEvent row on an **independent
in-memory clone only**. Both attempts must fail. A fake no-op trigger with
the right name is not enough. Also enforce correct Current owner,
nextVersion higher than maximum Version, and no duplicate/extra/missing
Version-to-asset mappings.

**Positive state:** `DISPOSABLE_SEVEN_SCHEMA_INVARIANTS_ONLY`.
All returns preserve
`actualSourceSnapshotVerified:false`,
`formalPrismaDeployVerified:false` (this **byte-only checker** does not run
the separate Prisma CLI test), `provenanceVerified:false`,
`operationalGo:false`, `runtimeActivated:false`. Formal migration unit
test success is reported **separately** and must not flip these flags.

**BLOCKED cases:** missing/partial Auth candidate, missing or no-op
Audit append-only trigger, CAD Version/Current/SHA/nextVersion change,
broken FK, missing/tampered CAD/S3 export bytes, duplicate/extra
mapping, unsupported disk path, and synthetic transaction rollback. The
fault-injection test intentionally interrupts the candidate SQL inside a
disposable SQLite transaction and checks that no Auth table remains and
the CAD baseline is still consistent. It does not claim a real restore.
