# Issue #109 S3-3: existing CAD writes / isolation / atomic Audit

## Gate
S3-3 adds transaction-time authorization to the legacy Multipart POST,
Current PUT and Version DELETE repository writes without enabling it in the
operating server. Anonymous GET and Viewer are unchanged.

The **only** executable S3-3 test mode is a nonproduction loopback process:
NODE_ENV=development, G7_S3_AUTH_API_PREVIEW_ONLY=true,
G7_S3_CAD_PREVIEW_ONLY=true, G7_S3_MIGRATION_TEST_ONLY=true,
G7_AUTH_ENABLED=false, G7_CAD_WRITE_CUTOVER_ENABLED=false and the exact
S3-2 G7_S3_TEST_ORIGIN plus UID-owned /tmp/cad-g7-s3-*/fixture.sqlite.
DATABASE_URL and G7_S3_TEST_DATABASE_URL must match the disposable file URL,
with its 0600 manifest and canonical 0700 root. Follow README.md and S3-2.md
for creating the disposable formal seven-migration fixture.

**P2 content/Viewer alignment:** Set `CAD_STORAGE_PATH` to the exact
`$G7_S3_TEST_ROOT/cad`, `CAD_STORAGE_BACKEND=local`, and leave ALL
`CAD_S3_*` variables unset. The existing anonymous content GET/Viewer
uses the process-global `context().storage` at `CAD_STORAGE_PATH`.
The S3-3 preview now refuses writes if that root is missing, different,
S3-backed or ambiguous; neither environment nor process may reuse an
operating storage root. Start a **separate disposable process** so the
cached storage backend cannot refer to previous environment settings.

Runtime verifies migration, FKs, exact origin and the test target before
opening an independent Prisma client, and places uploaded files only in
<test-root>/cad. It never uses operating S3 or the global Prisma client.
Operating G7 enable/GO attempts without the later trusted release binding
are denied, not treated as a permission to fall back to legacy writes.

## Audit transaction
- Upload: validate authoritative Floor/Building/Site chain, freshly reload
  Actor/Role/Site Grant from DB, write Version/Current and CAD_UPLOADED Audit
  in one Prisma writeTransaction. Existing temp/publish compensation stays.
- Current: lookup Version->Location->Building->Site, authorize in transaction
  and update Current with CAD_CURRENT_CHANGED Audit together.
- DELETE: check permission *before* password evaluation, keep the original
  password AND Site rule, revalidate permission in the final DB transaction;
  clear Current/create deletion job/delete Version/CAD_VERSION_DELETED Audit
  in one atomic commit. Storage cleanup still follows existing 200/202 policy.
- Any Audit insertion failure causes all business SQL to roll back.
  Do not trust X-User, X-Role, claimed Site IDs or a previous cached grant.
  Session absolute 8h and idle 30m rules are checked inside transactions.

The S3-2 preview cookie has Path=/api/g7-operational for isolation.
Programmatic loopback tests must explicitly forward that test-only Cookie to
the legacy path; this does not enable a browser production cutover.
