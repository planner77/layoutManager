# #142 S3-4-B2-1 — offline OCI manifest/digest consistency preflight

## Scope and warning

This is **the first B2 implementation increment**, after #141 B1 merged on
Main `7469d016a5926aca07929bf3e95e869b46716bd1` and
[Main CI #40478523325](https://github.com/planner77/layoutManager/actions/runs/40478523325)
succeeded with release-scope SUCCESS and GHCR publishing SKIPPED.

This PR adds no release, registry connection, deployment, production migration,
real DB/CAD/S3 operation, or live G7 authentication. The function
`inspectS34B2OfflinePair` accepts **operator-collected raw OCI manifest and
image config bytes** and locally checks four exact `@sha256:` references.
Matching digest bytes is **not proof** that the bytes came from the named
registry, not an attestation/signature or valid rollback. Every output has
`registryVerified:false`, `provenanceVerified:false`,
`rollbackCompatible:false`, `sameSnapshotRestored:false`,
`operationalGo:false`, and `runtimeActivated:false`.

## Four image roles

- `app` / `migrator`: exact `ghcr.io/planner77/layoutmanager@sha256:<digest>`,
  same G7 source SHA and semantic version, expected capability
  `G7-S3-AUTH-V1` and quarantined Auth schema
  `202610260002_g7_operational_auth`.
- `rollbackApp` / `rollbackMigrator`: immutable digests and consistent
  prior source SHA/version, explicitly `CAD_BASELINE` capability/schema
  in this **synthetic** initial compatibility contract. Actual rollout
  rollback schema compatibility must be verified separately.
- All four raw image manifests must be OCI or Docker schema-v2
  single-platform image manifests and config bytes must match their
  digest/size. All configs require Linux/amd64 and explicit revision,
  semantic version, capability, schema-id and image-role labels.
- `latest`/tag-only, other registry, image index without resolved platform,
  changed bytes, missing roles, invalid SHA/schema, same rollback identity
  are BLOCKED; output never includes raw blobs, private registry URLs or
  original evidence.
