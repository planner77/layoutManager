# Issue #109 — S3-2 reserved Auth/Admin API integration (operating OFF)

## Scope and safety

S3-2 reserves `/api/g7-operational/{auth,access,users}/*` with real G3 Login/
Session/Password/Logout, G4 Role/Site/SpecialGrant, account disable, Audit and
transactional Admin-only account creation. This is a **nonproduction preview
of the operational API contract**, NOT actual S3 runtime activation.

`NODE_ENV=production` unconditionally returns 404 regardless of all G7_*
environment values, claims or cookies. The S3-1 pure release/operation
preflight still returns `runtimeActivated=false`. Auth activation requires
a later S3-4 verified App/Migrator OCI pair, actual DB/migration/rollback
evidence and release-specific Owner GO. Existing CAD GET/Viewer and all
existing CAD POST/Current/Version DELETE paths are unchanged.

## Isolated Linux testing only

Follow `src/deploy/g7-s3/README.md` to create a private, UID-owned
mode-0700 `/tmp/cad-g7-s3-*/` directory with a mode-0600 `fixture.sqlite` and
`s3-disposable.json` manifest. The S3-1 candidate Prisma history contains
six CAD migrations and one additive S3 Auth migration. Apply ONLY with:

```bash
cd src
export G7_S3_MIGRATION_TEST_ONLY=true
export G7_S3_TEST_ROOT=/tmp/cad-g7-s3-<actual-directory>
export G7_S3_TEST_DATABASE_URL="file:$G7_S3_TEST_ROOT/fixture.sqlite"
export DATABASE_URL="$G7_S3_TEST_DATABASE_URL"
export G7_AUTH_ENABLED=false
export G7_CAD_WRITE_CUTOVER_ENABLED=false
npx prisma migrate deploy --config deploy/g7-s3/prisma.config.ts
```

The Prisma config and API preview share `disposable-target.ts` for DB
realpath, UID, mode-0600 marker, canonical root, schema ID, nonce and exact
two DB URL checks. An invalid target is denied **before SQL**. Neither
`src/prisma/migrations` nor the ordinary automatic migrator is modified.

For isolated HTTP preview only (a separate local Next dev process):

```bash
export NODE_ENV=development
export G7_S3_AUTH_API_PREVIEW_ONLY=true
export G7_S3_TEST_ORIGIN=http://127.0.0.1:3317
# Run a separate instance on 127.0.0.1, never expose it to a LAN or internet.
```

The preview requires both explicit gates and an exact loopback origin.
It is disabled for a production build, non-loopback origin, missing
migration, forged/partial manifest, unapproved DB path, Auth/Write cutover
flags ON or Owner operation approval IDs.

## One-shot Admin on disposable DB only

Create a private mode-0600 secret and use one of G2's explicit modes.

```bash
export ADMIN_BOOTSTRAP_ENABLED=true
export ADMIN_BOOTSTRAP_USERNAME=stageadmin
export ADMIN_BOOTSTRAP_PASSWORD_FILE=/absolute/private/admin.secret
npx tsx scripts/g7-s3-admin.ts --ack-disposable-only
unset ADMIN_BOOTSTRAP_ENABLED
```

For recovery, supply `ADMIN_RECOVERY_ENABLED=true`, the target Admin
`ADMIN_RECOVERY_TARGET_USER_ID`, a one-time `ADMIN_RECOVERY_ONCE_ID`
and restricted `ADMIN_RECOVERY_PASSWORD_FILE`, with the same explicit CLI
argument. Recovery consumes the nonce, revokes sessions and records Audit
atomically. No password/token/secret content is output. The CLI is
NEVER invoked at app start, Docker migrator or operational deployment;
there is NO production Admin CLI in S3-2.

## Test-only HTTP contract

| Method | Reserved endpoint | Required checks |
| --- | --- | --- |
| POST | `/api/g7-operational/auth/login` | scrypt password, durable limiter, session hash |
| POST | `/api/g7-operational/auth/initial-change` | one-time initial password update |
| GET | `/api/g7-operational/auth/session` | DB Actor, session validity and CSRF |
| POST | `/api/g7-operational/auth/change` | old password+CSRF, revoke+Audit |
| POST | `/api/g7-operational/auth/logout` | session revoke and expire preview cookie |
| POST | `/api/g7-operational/users/create` | Admin only; initial password; User+Audit one transaction |
| POST | `/api/g7-operational/access/grant` | Admin, role/site/special grant and Audit |
| POST | `/api/g7-operational/access/disable` | Admin, disable/revoke and Audit |
| POST | `/api/g7-operational/access/permit` | DB-resolved Actor/Role/Site/Version |
| POST | `/api/g7-operational/access/audit` | Admin plus audit:read special grant |

The isolated preview cookie is `cad_g7_s3_session` (HttpOnly,
SameSite=Strict, Path=/api/g7-operational), translated internally to
G3/G4's established `cad_session` name. The existing `cad_session` and
S1 `cad_staging_session` are ignored; they cannot authenticate S3.
Sessions remain 8-hour absolute, 30-minute idle and max 3 concurrent.
Roles and scopes are read from the DB, not X-Role/X-User or request body.

New accounts start with no role and must change their initial password.
Admin account creation uses the existing G4 users:manage permission with
DB Audit BEFORE password hashing, then rechecks the Admin session/Role
inside the same transaction as User and ACCOUNT_CREATED Audit insertion.
Role, Site and SpecialGrant administration use the existing G4 adapters.
G4's synthetic Outline operation is NOT exposed through S3-2.

No CAD upload/Current/DELETE business mutations and no Outline/Memo/Type/Logs
durable APIs or Audit physical purge are exposed by these routes.
