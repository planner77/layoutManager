## Scope and non-goals

S3-4 consists of separate, sequential gates: **A** offline evidence bundle
contract and fail-closed checks (this PR); **B** privately executed immutable
OCI App/Migrator provenance, candidate migration on an approved *clone*,
actual DB/CAD/S3 SAME-SNAPSHOT restore and rollback verification; **C**
trusted binding of independently verified release artifacts and Owner's
release-specific GO before S3-5 field activation. A completed S3-4-A
packet NEVER means B/C passed or that production migration/operation is approved.

This PR has **no registry client, no Docker pull/build, no S3 API calls, no
Prisma migration command and no runtime route**. It does not change
`src/prisma/migrations/**`, `src/scripts/deploy.ts`, Compose, Nginx,
operating database/CAD/S3, release images, tags or secrets. The S3-1 7th
migration remains quarantined in `src/deploy/g7-s3/prisma/migrations/**`.

## Required private evidence bundle

`src/server/g7-operational/s3-4-readiness.ts` defines a strict schema:
- `schemaVersion=1`, `scope=G7_S3_4_READINESS`,
  `capability=G7-S3-AUTH-V1`,
  `schemaId=202610260002_g7_operational_auth`.
- `sourceCommit` (40-character lowercase Git SHA), `snapshotId` (same
  `SNAP-...` across DB/CAD/S3 restore checks).
- `operationalActivationOff=true`, `activeMigrationUnchanged=true`;
  any other value blocks packet completeness.
- `app`, `migrator`, `rollbackApp`, `rollbackMigrator`, each with
  `version`, `sourceCommit`, `digest=sha256:<64 lowercase hex>`.
  App and Migrator must have matching version/source, rollback App+Migrator
  must also match, and the rollback pair cannot be identical to forward pair.
  `latest` tags are NOT digests.
- `checks` must use all names exported as `S3_4_REQUIRED_CHECKS`.
  Each item has `status=PASS|FAIL|NOT_RUN|CANCELLED`.
  PASS requires a *real private* `EV-...` evidence ID, `QA-...`
  reviewer ID, UTC verification timestamp, and for restore/snapshot checks
  the **same** `snapshotId`. Do not generate synthetic or fabricated IDs.

The required checks include registry-verified immutable App/Migrator and
rollback digests, paired source/version consistency, six existing CAD
migration files identical by bytes, isolated 7th candidate, disposable
migration dry-run, DB/CAD/S3 same snapshot, DB FK-zero and
Version/Current/original SHA, restored local and S3 object checks,
compatible rollback App/Migrator, Admin recovery/Secret SOP and 365-day Audit
retention/backup SOP. The form is a **pointer to private evidence**, not the
evidence itself. A `PASS` string with an ID is only an assertion; registry,
file and DB checks must be independently executed and retained internally.

## Offline execution — operator-controlled machine only

Store the filled JSON OUTSIDE the checkout, readable only by its owner
(mode 0600) at a canonical absolute path; never commit to Git/GitHub,
CI artifacts or an external assistant. On an independent Linux/WSL2
offline checkout, with Auth/Write/GO switches OFF:

```bash
cd src
npx tsx scripts/g7-s3-4-readiness.ts /absolute/private/s3-4-attestation.json
```

Output is only `state`, completed/required counts, reason **codes** and
`operationalGo:false`, `runtimeActivated:false`; no evidence contents,
credentials, file path, host/IP, original CAD, hashes or internal logs.
- `BLOCKED` (exit 2): invalid/failed/cancelled evidence, mismatched ID,
  incomplete schema or unsafe private file.
- `PENDING` (exit 3): absent or NOT_RUN checks (without other faults).
- `EVIDENCE_PACKET_COMPLETE_NOT_GO` (exit 0): operator attestations are
  structurally complete, **not independently verified** and still **NO-GO**.

## Private execution gates B/C (not performed by this PR)

1. Pick a specific build/source/Schema and **published** App/Migrator
   immutable OCI digest pair plus compatible rollback pair. Inspect
   image manifest/platform/source provenance from an authoritative registry;
   retain private verification record and match candidate SQL checksum.
2. Freeze writers consistently, take SQLite online backup plus local CAD and
   S3 object/version snapshot under a single ID. Backups taken at different
   instants without a quiescing/barrier protocol are NOT one snapshot.
3. Only on isolated duplicate volumes: apply all seven formal migrations;
   compare original CAD bytes/SHA, Site→Location→Version/Current, delete
   password hashes, Audit and FK=0. Simulate migration failure and actually
   restore the **same** DB/CAD/S3 snapshot, then validate rollback App and
   Migrator compatibility. Failure leads to fail-closed HOLD.
4. Owner-specific Release+Operation approval remains a separate S3-5
   operation: exact source, digest pair, Schema, snapshot, change ID, actor,
   24-hour-or-less window, responsible rollback operator and privately stored
   evidence. Without that GO, Auth and CAD Write flags stay OFF.

S3-4-A does not request a live CIDR, password, S3 keys, CAD or evidence
exfiltration. The S3-3 preview is disposable-only and unaffected.
Issue #109 and #96 remain **OPEN/BLOCKED**.
