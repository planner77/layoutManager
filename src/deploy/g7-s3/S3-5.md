## Stage decision boundary

consistency of a future, explicit, release-specific Owner decision.**
This step is separate from #153's actual S3-5 operating approval/cutover.

- Release must be a specific, locally identified **App+Migrator pair and previous
  rollback pair**, immutable digest for all four roles, source & rollback source
  Git SHAs, Schema/Capability, site Scope, single SNAP/Source Epoch and CR.
- Named internal Owner, operator, **distinct rollback operator**, approved-at,
  not-before and expiry UTC times with window **no longer than 24h**.
- A previously verified, still-valid S3-4-C0 signed 17-receipt packet must bind
  to **the same source/rollback, OCI pair, version, Schema, SNAP, Epoch and CR**.
- Separately provisioned on-site approved Owner/QA **Ed25519 Public Keys** verify
  C0 statements, and the Owner independently signs the **S3-5 release decision**
  statement. Release identity and site scope are also passed as an independent
  locally controlled trust configuration, NOT accepted from the packet.
- A statement claiming `NO_GO`, an altered/expired/future/>24h approval, missing
  or mismatched C0 packet, wrong key/signature, unknown field, same operator and
  rollback operator, or incomplete previous release evidence must fail closed.
- Good local signature **only** establishes
  `LOCAL_RELEASE_DECISION_CONSISTENT_NOT_ACTIVATED`. It does **not** indicate
