# #142 S3-4-B2-2B — Disposable independent bytes preflight (NOT site proof)

## Codex P2: S3 Object UUID and DB Version UUID are independent

- [PR #145 review #4388372985](https://github.com/planner77/layoutManager/pull/145#discussion_r4388372985): `S3ObjectStorage.prepare()` allocates `cad/<object-uuid>/original.ext` before registration. `CadRepository.register()` separately allocates its `CadFileVersion.id`. Those UUIDs are NOT required to match. The former is persisted inside DB `storage_path`, while `id` identifies the DB row.
- For **synthetic/disposable input only**, the S3 `ObservedObject` mapping now includes `s3ObjectLocator` (a bounded, strictly shaped `s3:bucket:cad/<object-uuid>/original.(dxf|dwg)` claim). The checker validates this independently supplied locator against the exact SQLite `CadFileVersion.storage_path`, expected file extension and provided S3-export bytes. It NEVER treats the object-key UUID as the DB Version ID. S3 bucket and object IDs are private input data and MUST NOT be returned, logged, or added to Git/Actions/chat.
- A Local object still uses the DB Location/Version ID path contract, and MUST NOT contain an S3 locator. Missing, malformed or URL-based S3 locator claims block; a different but syntactically valid S3 bucket/object locator fails against DB `storage_path`. Synthetic regression covers distinct valid object/row UUIDs and these fail-closed mutations.
- This is still `DISPOSABLE_BYTES_CONSISTENT_NOT_SITE_PROOF` on matching data, **not** proof of authenticated real S3 object, source writer freeze, genuine snapshot, or Owner GO. No real site, S3 API, writer stop, online backup, migration, Restore/Rollback or GHCR publish is authorized.

## Input and checks

- The first argument must pass the complete B2-2A untrusted Snapshot/Epoch/
  barrier time claims, SQLite/Current/Version inventory and Local/S3 manifest
  consistency validator. A B2-2A BLOCKED packet cannot be elevated.
- Second argument: scope G7-S3-4B2-B2B-DISPOSABLE-BYTES, same SNAP and epoch,
  in-memory SQLite bytes, one-to-one opaque L-* -> disposable SQLite location
  IDs, one-to-one opaque V-* -> disposable SQLite Version IDs, and a Local or
  S3 export Buffer for every Version. S3 object Version IDs are still **claims**.
- SQLite backup SHA-256 is recalculated from actual supplied bytes. Open the
  same verified Buffer as SQLite memory clone (no pathname reopen); check
  PRAGMA quick_check and foreign_key_check, complete Location and Version
  inventories, Current, next_version, version number, SHA-256, size, storage
  locator and Local/S3 kind. This step is scoped to **CAD baseline**; the
  Auth 7th migration and its append-only Audit tables are B2-3 territory.
- Recalculate SHA-256 and length for every supplied CAD local and S3-export
  Buffer independently against both packet-level Version and object claims.
  Cross-check S3 object VersionId claims; validate a small versioned marker
  Buffer contains the expected SNAP and epoch. Do not report these IDs as
  authenticated by S3: authoritative HeadObject/GetObject VersionId and
  immutable source origin are *NOT RUN*.
- Require exact record shapes and bounded arrays/Buffers; no raw path, bucket,
  credential or object ID is returned. Reject duplicate/missing/extra private
  mappings, invalid SQLite, FK, modified bytes, wrong marker/source epoch,
  Current/Version/locator mismatch and unsupported schema with safe reason
  codes and BLOCKED. No arbitrary external directory or S3 URL is accepted.
- Isolated fixture tests must include positive byte-copy consistency, changed
  DB/CAD/S3 bytes, missing/duplicate mappings, marker mismatch, source epoch
  mismatch, Current discrepancy, FK violations and Auth schema boundary.
