## Strict supplied-packet contract

The top-level record requires exactly: scope
G7-S3-4B2-5-DISPOSABLE-EVIDENCE, schemaVersion=1, snapshotId=SNAP-...,
sourceEpoch=E-..., changeRequestId=CR-..., operatorId=OP-...,
reviewerId=QA-..., submittedAtUtc, reviewedAtUtc, binding,
readiness, records. All opaque identifiers are bounded. UTC timestamps
must be canonical; reviewer time cannot precede submission.

readiness is the existing S3-4-A G7_S3_4_READINESS packet with G7 capability
and schema, operational flags OFF, four pair identities, and all seventeen
S3_4_REQUIRED_CHECKS. Binding is exactly the source and rollback Source SHA,
schemaId, snapshotId and four distinct immutable App/Migrator and rollback
App/Migrator digest references. Every field must match readiness.

records must contain exactly one item per required check. PASS entries must
have exactly name, status, EV-evidenceId, QA-reviewerId, observedAtUtc,
SNAP-snapshotId, sourceCommit and schemaId; the evidence/QA/SNAP/Source/Schema
must agree with the S3-4-A claim. testedAt <= observedAt <= reviewedAt;
testedAt <= submittedAt. Duplicate check or evidence references are blocked.
For NOT_RUN, FAIL and CANCELLED, entries may have only name and status.

Unknown, malformed, secret-bearing fields; missing/duplicate evidence,
wrong roles, swapped snapshot/EV/QA or source, invalid time, bad OCI digest,
mismatched state or tampered S3-4-A packet -> BLOCKED. Matching NOT_RUN claims
-> PENDING, matching FAIL/CANCELLED -> BLOCKED. The reconciled state is
never evidence authentication, signature verification or site PASS.
