# #142 S3-4-B2-2A — Snapshot writer-barrier assertion contract (production OFF)

## Scope

After B2-1 [PR #143](https://github.com/planner77/layoutManager/pull/143) merged
into Main `2d29b8572b02ccacf5e0032bf5432cb2f2b26ed6`, [Main CI

B2-2A adds `assessS34B22CapturePacket`, a **pure offline assertion
consistency validator**. It neither stops writers nor performs SQLite
online backups, S3 versioned GetObject/HeadObject calls, CAD directory
reads, or an actual Restore. This is NOT completed B2-2 field acceptance.
The entire supplied packet can be forged; even a consistent packet is
`CAPTURE_CLAIMS_CONSISTENT_NOT_SOURCE_PROOF`. All results permanently
have `writerQuiescenceVerified=false`, `sameSnapshotVerified=false`,
`bytesVerified=false`, `provenanceVerified=false`,
`operationalGo=false`, `runtimeActivated=false`.

## Offline packet contract

- Exact `scope=G7-S3-4B2-CAPTURE`, `schemaVersion=1`, opaque `SNAP-*`,
  `OP-*` operator and `CR-*` change request references. No site IDs,
  credentials, object paths or CAD file names are required or accepted.
- `barrier` contains `BAR-*` identifier, UTC millisecond timestamps
  `quiescedUtc/resumedUtc`, matching `E-*` source epochs,
  `activeWriters=0`, `writesDuringCapture=0`,
  `leaseClaimed=true`. These are **untrusted assertions**.
- SQLite, local CAD and versioned S3 **capture intervals** must fall wholly
  inside the writer-barrier interval and share one Snapshot ID and source
  epoch. The S3 snapshot marker MUST have its own nonempty version ID.
- SQLite packet claims `quickCheck=ok`, `foreignKeyViolations=0`,
  `currentOwnerViolations=0` and `auditInvariantViolations=0`.
  Version entries use opaque `V-*` and `L-*` keys, positive Version,
  byte size + SHA-256, local/S3 storage type. S3 entries need explicit
  version IDs; the actual CAD DB may not contain object version IDs —
  the private capture operator must map and verify them independently.
- The local/S3 object inventories must match the DB version entries
  one-to-one by opaque Version key, byte length, hash, and S3 object
  Version ID. Current must belong to the same location; `nextVersion`
  must exceed the highest Version. Unmatched extra or missing objects,
  duplicates, corrupted/partial inventories or invalid audit/FK flags BLOCK.

## Required future B2-2B true same-snapshot collection (NOT IMPLEMENTED)

1. Obtain site-specific Owner change control approval, agree controlled
   writer freeze across the app, background jobs, and any S3/CAD writer.
   Verify **independently** that writes are quiesced, record actual
   exclusive lease/epoch, UTC time and monitoring traces.
2. Use an authorized SQLite online backup procedure under that barrier;
   check transaction visibility, WAL/shm conditions, integrity, FK,
   Current/Version and Audit invariants directly against source or
   independently verified backup.
3. Capture local CAD immutable bytes and **versioned S3 objects**, marker
   and object version IDs during the same freeze; independently read and
   hash every selected original, match DB inventory, and reject missing
   objects/version truncation or concurrent mutation.
4. Restore the application to normal write mode only on approved
   procedure, retaining evidence privately. Feed only redacted opaque
   references and reason/status codes into public GitHub.
5. A later trusted binder must authenticate operator identity, observed
   snapshots and independent reviewer QA before treating any assertion
   as evidence. B2-3 candidate migrations and B2-4 restore/rollback
   need separate authorized disposable test infrastructure; they cannot
   be inferred from this contract.
