## 요구사항과 설계

### #124 목록
- 홈에서만 앱 내비게이션 + 제목/관리 액션 + 검색/필터/단일 Current 토글 + 결과 요약을 sticky로 유지한다. 앱 헤더와 목록 영역 높이를 실제 측정해 CSS 변수로 offset/scroll-padding/행 scroll-margin을 연동하거나 하나의 sticky 컨테이너로 구성한다. 타 경로 레이아웃은 변경하지 않는다.
- 기존 Arial/Noto Sans KR, 배경 #f5f7fa, 글자 #172b3a, 보조 #475569, 경계 #dce2e8, 강조 #0f766e를 유지. 목록 스코프에만 36px desktop control/짧은 label gap·padding, mobile touch 크기를 적용. 제목·CTA 한 행, 검색 두 입력+actions, 위치/형식/pageSize 정렬, 요약 간격 축소. 장식용 eyebrow 제거.
- 작은 폭/낮은 높이에서는 추가 필터 접기/펼치기, 핵심 검색·Current/요약 접근 유지. 접힘으로 form 필드/선택값을 제거하지 않는다. 두 독립 GET form, versions=all/초기 Current/토글 page=1/검색·Back·Reload 의미와 행 anchor 보존. 메뉴/포커스 clipping 없음.

### #126 DXF 복구
- selectRenderer를 단일 기본값 기준으로 사용: DXF 미지정/빈 값/잘못된 query → three-dxf-viewer, 유효 explicit dxf-viewer 보존, DWG 항상 libredwg-web.
- source GET 오류와 adapter init/load/Worker 예외를 구조화된 단계/이유 코드로 구분한다. Three 실제 renderer 실패 때만 자동 dxf 재시도 최대 1회. 취소/Version 변경/unmount/source 오류는 자동 대체하지 않으며, 두 렌더러 실패는 원인과 수동 재시도·다운로드·명시적 dxf 새 링크를 제공한다.
- **타이머 정책:** 정상 대형 실측 근거가 없으므로 임의 timeout/MB threshold를 도입하지 않는다. 응답 없는 작업은 로딩 UI의 명시 중단·반대 DXF 렌더러 전환으로 탈출한다. 사용자 수동 탈출은 양방향이며 자동 대체는 Three→dxf 한 번뿐이다. JS 전체 정지/OOM은 복구 보장하지 않으며 명시적 dxf 링크가 대응 수단이다.
- 전환은 generation/abort+Adapter dispose를 거쳐 진행. 늦은 성공/오류/Canvas 부착이 현재 렌더러를 덮지 않도록 보장한다. 이미 다운로드한 bytes는 같은 ViewerSource 재사용. 미완료 GET abort 이후 안전한 재시작은 허용하되 완료 bytes fallback의 추가 GET은 0.
- 성공/실패/부분 상태 및 실제 renderer/URL/복사 링크를 일치시키며 안전한 이유·attempt 계측. 미저장 Generated/Undo/선택 상태가 있을 때 사용자 수동 전환/재로드는 손실 사전 확인. 자동 fallback은 초기 편집 상태 없는 load에만 적용한다.
- dxf 보기/Zoom/Pan/Fit/다운로드/링크/검증된 검색 유지. Three 전용 Layer/Outline/selection/edit/tree는 disabled + 구체적 지원 이유, 운영 관리자 항목도 승인되지 않은 상태 유지.

### #127 Viewer
- 상시 정보는 도면명·원본 파일명 2개. 도면명 button의 hover/focus/touch로 설명 tooltip을 열고 안전한 text+pre-wrap, bounded scroll, 빈 설명 생략. 긴 이름 전체값 접근 제공. Version/위치/용량은 정보 메뉴/상태로 이동.
- 상단 그룹은 도면 / 보기 / 작업. 실제 menuitem/link/check/radio로 기존 동작을 모두 연결한다. 관리자 타입 항목은 disabled 이유. keyboard Enter/Space/Arrow/Home/End/Escape/Tab·외부 클릭·트리거 focus 복귀. Portal 필요 시 Viewer shell subtree 안으로 제한해 native fullscreen 보존.
- 좌 Layer/우 Outline Tree/하단 선택·생성·편집 도구를 Canvas 위 가장자리 overlay Drawer로 배치. desktop non-modal, 제한 폭/높이·내부 scroll·명시 닫기. 작은 화면은 한 Drawer만 modal/focus trap, 닫기 후 그룹 trigger 복귀. Canvas를 dock 폭/높이로 축소하지 않는다.
- layerPanelOpen 기본 true, outlineTreeOpen false, outlineToolEnabled false 유지. 하단 Drawer open 별도 상태; 생성 OFF에도 허용 generated 편집 접근. Drawer 개폐와 layer visibility/selection/document/undo는 독립, Canvas DOM·Manager/Source/Worker load effect는 불변.
- ESC는 최상위 한 계층만 처리: submenu/tooltip/confirm/context/search/선택/Drawer/native/CSS의 실제 활성층에서 consume하고 뒤 계층 중복 처리 금지. 검색/선택의 기존 ADR-033 우선순위를 보존한다. 모든 overlay는 shell 내부, 시각 z-index·hit-test·loading 탈출 동작 검증. 삭제 확인창은 inert Canvas와 별도인 shell overlay 층에 두고, 열린 동안 하위 Drawer의 모달/Tab trap을 중단하며 닫은 뒤 포커스를 복원한다.

## 증거와 완료 판정
- 사전 baseline screenshot/height/Canvas area는 구현 전 별도 baseline build/checkout 또는 변경 전 환경에서 확보한다. 생성 fixture만 사용하고 PNG/DB/CAD/build output은 Git 제외, 수치와 실행 조건만 TestReport에 기록한다.
- 모든 관측 실패/원인/보완/재검증은 FailureLedger에 누적. 테스트 삭제·미실행을 PASS로 대체하지 않는다.
- 최신 HEAD PR CI Verify/Docker success, 리뷰/충돌 해결 및 Main CI/실제 GHCR paired promotion은 Root가 별도 확인한다. 현재 문서 기록은 출시 완료 증거가 아니다.
