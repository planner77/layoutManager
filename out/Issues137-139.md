## #139 — DXF text index encoding / P1
The former DXF text-index decoder matched DWGCODEPAGE within 32 KiB and always selected legacy euc-kr for ANSI_949, even for R2007+ UTF-8 DXF. It also reported unsupported labels and invalid input bytes as the same problem.

The new client-side decoder scans ASCII HEADER group-code pairs: code 9 for the header variable, code 1 for ACADVER, code 3 for DWGCODEPAGE. AC1021+ or UTF-8 BOM overrides stale ANSI metadata; older files use declared 949→euc-kr (Windows-949), 932→shift_jis, 936→gbk, 950→big5 and ANSI_12xx→windows-12xx. Missing metadata tries strict UTF-8 only, never silent replacement. Unsupported legacy labels, missing decoder, invalid bytes and Binary DXF have distinct safe messages.

No original CAD rewrite, backend API, Worker/ViewerSource cache architecture, renderer selector or focus math changes. Synthetic Unit cases cover R2007+ UTF-8 Korean, legacy CP949 byte sequence, other stale 932/936/950 headers, BOM, absent HEADER and broken/unsupported input. Actual field DXF root cause is unverified.
