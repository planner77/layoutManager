## Primary-source contract

- [Playwright Docker documentation](https://playwright.dev/docs/docker) recommends a nonroot user and its seccomp profile for Chromium sandboxing with untrusted sites; its image is described as a development/test image and not recommended for visiting untrusted sites. The [versioned Playwright v1.63.0 profile](https://github.com/microsoft/playwright/blob/v1.63.0/utils/docker/seccomp_profile.json) permits `clone`, `setns`, and `unshare` beyond its baseline. This documentation does not establish this application's runtime safety.
- [Chromium SwiftShader documentation](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md) says software WebGL fallback uses JIT code in the GPU process, reduces security guarantees, and is not intended for untrusted content. `--enable-unsafe-swiftshader` is an explicit opt-in; a working Chromium renderer sandbox does not remove that warning.
- [dxf-parser 1.1.2 package documentation](https://www.npmjs.com/package/dxf-parser) supports Node `parseSync`, common 2D entities, layers, blocks/inserts, TEXT and some MTEXT, but does not provide the project's Three.js geometry, glyph, material, source selection index, or `CUSTOM_DTO` contract. [Its upstream repository](https://github.com/gdsestimating/dxf-parser) is the parser source. The existing locked `three-dxf-viewer@1.0.44` depends on [dxf 5.3.0](https://github.com/skymakerolof/dxf), which also supports Node parsing; its own documentation excludes text, hatches, dimensions, and styles from SVG output. Parser support is not renderer support.

Each command selected one seccomp profile with `--security-opt seccomp=...`. ### Reproducible test-only probe

The checked-in [`sandbox-profile.mjs`](../src/tests/a2/sandbox-profile.mjs) verifies both pinned file SHA-256 values and the exact single-rule JSON difference. [`sandbox-probe.mjs`](../src/tests/a2/sandbox-probe.mjs) then starts a disposable container with the limits above, checks them with Docker inspect (including no added capabilities, no unexpected mounts, and private IPC), and runs [`sandbox-child.ts`](../src/tests/a2/sandbox-child.ts). It uses `A2_SANDBOX_RUN_ID` as an exact owned-container label and removes any matching container even if Docker launch fails before returning an ID. A CI cancellation trap must also clean that exact label because a terminated supervisor cannot execute its `finally` block. The result separates a sandboxed candidate conversion/readback from the expected fresh live restore failure; the report is always `RESEARCH_ONLY_NO_GO` or `PROBE_FAILED`, never secure GO. The existing unsafe A2 fault suite is separate and unchanged.

From the repository root, with Docker and the proof-image build dependencies available:

```sh
docker build --platform linux/amd64 -f src/tests/a2/Dockerfile -t layoutmanager-a2-proof:issue218-sandbox .
cd src
node --test tests/a2/sandbox-profile.test.mjs
A2_PROOF_IMAGE=layoutmanager-a2-proof:issue218-sandbox \
  A2_SANDBOX_RUN_ID=local-issue218-sandbox-1 \
  A2_SANDBOX_REPORT_DIR=/tmp/issue218-sandbox-report \
  node tests/a2/sandbox-probe.mjs
```

The JSON result is `/tmp/issue218-sandbox-report/sandbox-probe.json`. The pinned official profile is [Playwright v1.63.0](https://github.com/microsoft/playwright/blob/v1.63.0/utils/docker/seccomp_profile.json), SHA-256 `cc3e61cabda6bbc1e53e54d27ba4d55a9d3be829b6dd1a596f4a7b31b1cc7849`; the checked-in targeted file is SHA-256 `13e864cee59fd91b1fb03e63c292d590d42a1317aa3afa059f5f5d564e6d3ed4`. ## Node parser alternative

In a separate temporary `/tmp/issue218-node-parser` install, `dxf-parser@1.1.2` `parseSync` succeeded on the same synthetic fixture: model entities `LINE,CIRCLE,LWPOLYLINE,INSERT,INSERT,TEXT,MTEXT`, two nested block definitions, `$INSUNITS=4`, and Korean TEXT/MTEXT strings. The already locked `dxf@5.3.0` `parseString` succeeded on that fixture with the same seven model entity kinds and two blocks. Neither probe built a Three `Object3D`, glyph geometry, source selection index, material, `CUSTOM_DTO`, or fresh Adapter restore; no performance, memory, fault, malformed-file, OCS, CP949, HATCH, SPLINE, DIMENSION, or customer drawing claim follows. The earlier direct Node `three-dxf-viewer` path remains NO-GO because it had four unhandled `window is not defined` asynchronous errors, not resolved by these parser calls. An independent Node converter would require a new, reviewed geometry/text adapter and full parity and process tests before it could replace Chromium.
